LEFT 4 DEAD 1 & 2

Install game add-ons

  1. Check the listing’s game and required items. Follow its author’s instructions for any special installation steps.
  2. For an L4D2 Workshop item, select Subscribe on Steam. Start L4D2 and let it finish downloading the add-ons.
  3. For a manual .vpk, close the game and extract the VPK if it arrived in an archive. In Steam, use Manage → Browse local files on the matching game. Copy the VPK into left4dead\addons for L4D1 or left4dead2\addons for L4D2.
  4. Launch the game and check its Add-ons menu. If two replacements change the same model, texture, or sound, enable one at a time.
Browse Left 4 Dead add-ons → Valve’s L4D1 VPK instructions ↗ Valve’s L4D2 VPK instructions ↗

LEFT 4 DEAD 1 & 2

Start a custom campaign

Install every part of the campaign and enable it in Add-ons. When starting a game, choose Add-on Campaign in the campaign picker. For co-op, each player needs the same release of the campaign and its dependencies.

LEFT 4 DEAD 1 & 2

Textures, skyboxes and materials

For a VPK or Workshop item, use the game add-on steps above. For a Hammer kit, extract its materials folder into left4dead or left4dead2 inside the matching Steam game folder. Preserve the supplied paths so each .vmt can find its .vtf textures.

Open Hammer from the matching game’s Authoring Tools. For a skybox, set Map → Map Properties → SkyBox Texture Name to the value in the kit’s INSTALL.txt. For a brush material, select the supplied material in the Texture Browser. Include the kit’s required files when distributing your map.

Browse skyboxes → Browse textures →

LEFT 4 DEAD 1 & 2

Sound replacements

Check which sound the pack replaces and install it using its Workshop or VPK instructions. Test it with any other packs for that sound disabled. Keep the original folder layout for packs distributed as loose audio files and use the author’s instructions for their destination.

LEFT 4 DEAD 1 & 2

Source console presets

  1. Download the .cfg file and check its game label. In Steam, use Manage → Browse local files on the matching game.
  2. Place the file in left4dead\cfg for L4D1 or left4dead2\cfg for L4D2.
  3. Start the game, enable the developer console in Options → Keyboard/Mouse, and open it. Run exec followed by the filename, for example exec my-preset.cfg.
Browse Left 4 Dead configs → Scooby profiles and folders →

SCOOBY FILES

Config profiles

  1. Match the game, file format and required Scooby version.
  2. Use the game’s config library and its Open Folder or Import control.
  3. Back up your current settings, copy the complete profile, refresh the library and load the config.

Each game has its own supported settings. Use the active game’s folder control to find its profile directory.

SCOOBY FILES

Lua scripts

  1. Check the resource’s download state, game, required Scooby version, host API and Lua runtime.
  2. A listing marked Download pending has no installable download yet. Its source listing and changelog provide context; wait for a matching package before installing.
  3. For an available script, review the package and use the script library’s folder control. Preserve supporting modules and filenames.
  4. Refresh the script library and run the script from that library.

Use your game’s script library folder control and its supported scripting API.

Use a native Scooby script or a compatibility target supplied by your current build. Cherax and Stand scripts require their matching compatibility layer and supported API calls. Check the resource’s requirements; a listed source script may use features outside that layer.

SCOOBY FILES

Translations and languages

  1. Choose a translation catalog that matches your game and Scooby build.
  2. Use the language library’s Open Folder or Import control and copy the full package.
  3. Preserve filenames and supporting files, refresh the library and load the language.

Translation catalogs and layouts must match the host build. Keep any existing custom language overrides.

SCOOBY FILES

Other resource files

  1. Check the resource’s game, required version and included readme.
  2. Use the relevant Open Folder or Import control and preserve the full package’s filenames and supporting folders.
  3. Follow the author’s instructions for that resource type.
