Use Scooby on Linux & Mac

Setup, launch commands and troubleshooting for Linux, Steam Deck and Mac.

Use Scooby on Linux & Mac

Use the Scooby compatibility preview to launch the Windows loader through Wine or Proton. The loader and your Windows game must use the same prefix and the same runner. A prefix is the folder that holds a game's Windows files, settings and installed components; the runner is the Wine or Proton version that opens it.

Compatibility preview

This is the Windows x64 loader with Linux, Steam Deck and Mac launch scripts. Real-host login, graphics and in-game loading still need validation; no game is certified by this package yet. Opening the loader does not confirm that a game's menu will work.

Windows-only cleaner, identifier and kernel-driver tools are unavailable. Native Linux or Mac games cannot load the Windows game DLLs.

Before you start

  1. Get the compatibility package. Check the official Scooby downloads for Scooby-compatibility.zip. If only the standard Windows installer is available, ask Scooby support for the compatibility preview before following the commands below.
  2. Extract the whole ZIP. Keep linux/launch.sh, the Python launcher files and linux/bin/ScoobyLoader.exe together. Leave all bundled runtime DLLs beside the EXE; copying the EXE alone is not enough.
  3. Check Python. Run python3 --version in a terminal. The launch scripts need Python 3.10 or newer. If needed, install it using your system's supported package manager.
  4. Run the Windows version of your game once with the Wine or Proton setup you intend to use. Confirm the game opens on its own before adding Scooby. The loader requires a prefix capable of running 64-bit Windows applications.
  5. Open a terminal in the extracted folder that contains the linux folder. All commands below start there. Run them as your normal desktop user, without sudo.

Linux: Steam / Proton

  1. Install Steam and Protontricks using the supported instructions for your distribution. If you installed Protontricks as a Flatpak, use the Flatpak commands below.
  2. In the game's Steam Properties → Compatibility, select the Proton version you use for the Windows game. Start the game once so Steam creates its prefix.
  3. Find the game's numeric App ID by running:
protontricks -l

Replace APPID below with the number shown for your installed game. First check the local setup, then launch:

sh linux/launch.sh --runner proton --appid APPID --diagnose
sh linux/launch.sh --runner proton --appid APPID

Protontricks selects the game's prefix and Proton runtime from its App ID. Always launch the game through its existing Steam entry. A separate non-Steam shortcut for Scooby can create a different prefix, leaving the loader unable to see the game.

If you configured a custom Steam compatdata location, add --compat-data with the directory containing pfx, not the pfx folder itself:

sh linux/launch.sh --runner proton --appid APPID --compat-data "/path/to/compatdata/APPID"

Replace every example path with your actual path and keep the quotes when it contains spaces. Proton mode uses --appid; do not combine it with the Wine-only --wine or --prefix options.

Steam Deck / Flatpak Protontricks

  1. On Steam Deck, switch to Desktop Mode and install Protontricks through Discover. Keep SteamOS in its normal read-only state.
  2. Check that python3 --version reports 3.10 or newer, extract the compatibility package, and start the Windows game through Steam once.
  3. Open a terminal in the folder containing linux and list your games:
flatpak run com.github.Matoking.protontricks -l

Use your game's numeric App ID in both commands:

sh linux/launch.sh --runner proton --flatpak --appid APPID --diagnose
sh linux/launch.sh --runner proton --flatpak --appid APPID

These commands also apply to desktop Linux when Protontricks is installed as a Flatpak. The launcher grants access to its bin folder for that run. A Steam library on an SD card or another drive may need additional access in Protontricks' Flatpak settings.

Start with Desktop Mode and a mouse or trackpad. Game Mode switching, controller navigation and suspend/resume are not yet verified.

Linux: Wine / Lutris for non-Steam games

Use the existing prefix and exact Wine runner used by the game. For example, if GTA V is installed through Rockstar Games Launcher in Lutris, use that Rockstar/GTA V prefix.

  1. Start the game through its existing Wine or Lutris entry once and confirm it works.
  2. In Lutris, open the game's configuration and note its Wine prefix and selected Wine version. Use the executable belonging to that runner, not an unrelated system Wine installation.
  3. Replace the paths below with the runner's Wine executable and the game's prefix folder, then check and launch:
sh linux/launch.sh --runner wine --wine "/path/to/wine" --prefix "/path/to/game-prefix" --diagnose
sh linux/launch.sh --runner wine --wine "/path/to/wine" --prefix "/path/to/game-prefix"

The prefix path is the folder containing drive_c, not drive_c itself. Omit --wine only if the wine command on your PATH is the same runner used by the game.

For a Lutris shortcut, add a locally installed game using the Wine runner, choose the extracted linux/bin/ScoobyLoader.exe, and set the same Wine prefix and Wine version as the game. Keep the runtime DLLs beside the EXE. Do not use plain Wine on a Steam Proton prefix.

The launcher uses an existing prefix; it does not create, convert or repair one. A 32-bit-only prefix cannot run this loader.

Using Scooby after setup

  1. Launch Scooby with the same command or configured Lutris entry each time.
  2. Sign in with your Scooby account or use the free-key instructions. Existing account and product access rules still apply.
  3. Start the Windows game through the Steam, Wine or Lutris setup you selected above. Follow your game's Scooby guide for when to load its menu; the required timing differs by game.
  4. If the game is not found, check the App ID, prefix and runner before trying again. Sharing a prefix is necessary, but it does not guarantee game or DLL compatibility.
  5. Close both Scooby and the game before changing their Wine or Proton version.

Settings and files: Windows paths such as C:\scooby live inside the selected prefix at drive_c/scooby. Each prefix has separate data. If you receive an HWID mismatch after moving from Windows or changing prefixes, follow the HWID reset guide.

Updating: close the loader and replace the compatibility package with the latest compatibility build from Scooby. Keep its files together. This build does not automatically replace itself with the standard Windows loader, and a required minimum version can block an outdated package.

Troubleshooting

The launch script or EXE cannot be found

Make sure the ZIP is fully extracted and your terminal is in the folder containing linux. Check that linux/bin/ScoobyLoader.exe and its bundled DLLs are present. A standard Windows download alone does not include these launch scripts.

Python or the runner is missing

Check python3 --version. For Proton, install Protontricks; if it came from Discover or Flatpak, include --flatpak. For Wine, correct the --wine path to the game's installed runner.

The game is missing or the prefix is rejected

Start the Windows game once with its selected runner. Check the Steam App ID or Wine prefix path. A prefix must be initialized and support 64-bit applications. For custom Steam locations, --compat-data points to the parent of pfx. Check Flatpak access if your library is on another drive.

Missing text, a blank window or a graphics error

Keep the packaged runtime DLLs next to the loader and check the selected runner's graphics support. If Segoe UI text is missing, install a copy of segoeui.ttf that you are licensed to use into that same prefix's drive_c/windows/Fonts folder, then restart the loader. Proton supplies its own graphics components; this launcher does not install DXVK or set graphics DLL overrides.

The loader opens, but the menu does not load

Confirm you are running a Windows game, using its correct Scooby build and following that game's loading instructions. Game, DLL and graphics-backend compatibility still need testing under the selected runtime. Some games or anti-cheat systems do not support Wine/Proton; this package does not change those restrictions.

Check the setup before reporting a problem

Add --diagnose to your launch command to print a report without starting Scooby. It checks local files, options and the runner executable, plus an explicitly supplied prefix. It does not test login, graphics, game loading, Steam's automatically selected prefix or Flatpak permissions.

When contacting Scooby support, include your Linux distribution or SteamOS version, GPU, Wine/Proton version, game edition/App ID and the exact error. Remove private paths or account details before sharing reports; never include passwords or license keys.

Performance

Check how the game runs without Scooby first, then compare with the same settings and runner. Performance can vary with the game, graphics backend, drivers, Wine/Proton version and enabled menu features.

If you test another runner, close the game and loader first. Select Proton through Steam or Wine through your game manager, and make sure Scooby uses the same selection when you reopen it.

Mac

The package includes a macOS Wine entry point. You need Python 3.10+ and a Mac-compatible Wine distribution that can run Windows x64 applications. On Apple silicon, x64 execution and graphics translation depend on that distribution. Actual Mac compatibility remains unverified.

Use the game's existing prefix and its Wine executable. From the extracted folder containing linux, replace both paths and run:

sh linux/mac/launch.command --wine "/absolute/path/to/wine" --prefix "/absolute/path/to/game-prefix" --diagnose
sh linux/mac/launch.command --wine "/absolute/path/to/wine" --prefix "/absolute/path/to/game-prefix"

The script needs those arguments; double-clicking it does not configure a bottle. If your runner requires CrossOver-specific bottle or environment settings, use that vendor's setup for the same game bottle. The script does not automatically configure arbitrary CrossOver bottles. Proton mode is Linux-only.
